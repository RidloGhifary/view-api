# Code of Conduct

## Our Pledge

View API should be welcoming, respectful, and productive. Everyone participating in the project should communicate professionally and respectfully.

## Expected Behavior

Examples of expected behavior include:

- Being respectful.
- Giving constructive feedback.
- Asking questions clearly.
- Helping others when you can.
- Staying focused on the issue, pull request, or discussion.
- Being open to different opinions.
- Accepting feedback gracefully.

## Unacceptable Behavior

Examples of unacceptable behavior include:

- Harassment.
- Insults.
- Personal attacks.
- Discriminatory language.
- Threats.
- Trolling.
- Disruptive comments.
- Publishing private information.
- Sexualized language.
- Dismissing people based on experience level.
- Hostile communication.

## Technical Disagreements

Technical disagreements are normal and often useful. Keep the discussion focused on the problem, trade-offs, implementation, and user impact. Do not attack the person making the suggestion.

Acceptable examples:

- "I think this approach may make `/__config` harder to keep backward-compatible. Could we preserve the existing field shape?"
- "This adds a dependency for a small feature. Can we solve it with the current code first?"
- "The UI behavior works, but I am concerned about update loops in the editor."

Unacceptable examples:

- "Only someone inexperienced would write it this way."
- "This idea is stupid."
- "You clearly do not understand the project."

## Enforcement

Maintainers may take action when behavior is harmful to the project or community. Depending on the situation, maintainers may:

- Remove comments.
- Hide disruptive content.
- Close issues or pull requests.
- Give warnings.
- Temporarily restrict participation.
- Permanently ban users if needed.

- Where it happened.
- Who was involved.
- Links to comments, issues, or pull requests.
- Screenshots, if relevant.
- Additional context.

## Scope

This Code of Conduct applies to official project spaces, including:

- GitHub issues.
- Pull requests.
- Discussions.
- Comments.
- Community chats.
- Project-related communication.

## Maintainer Responsibilities

Maintainers are responsible for helping keep the project healthy and productive. Maintainers should:

- Apply rules fairly.
- Avoid favoritism.
- Keep discussions productive.
- Protect contributors from harassment.
- Respond thoughtfully.
- Keep enforcement proportional.
- Not use the Code of Conduct to silence respectful technical disagreement.

## Our Goal

View API is a developer tool. The project should stay practical, useful, and welcoming.

Be direct. Be respectful. Keep it productive.
